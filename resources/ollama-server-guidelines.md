# Local LLM Server
## Usage Guidelines

Welcome to our shared learning resource! 🎓

---

## Purpose of This Server

This local LLM server is provided as a **shared educational resource** for all students in the course.

**Goals:**
- Support your learning and coursework
- Provide hands-on experience with LLMs
- Enable experimentation and exploration
- Foster a collaborative environment

---

## Core Principle: Good Faith Use

**Good faith** means using the server:
- As intended for educational purposes
- With consideration for fellow students
- Responsibly and ethically
- Within the spirit of academic integrity

---

**We trust you to be good stewards of this resource.**

# Please don't run malicious, harmful or disruptive API commands

Please ask if you want a new model to be available.

---

## Fair Use Guidelines

### 1. **Share the Resource**
- Others are waiting too
- Be mindful of server load
- Don't monopolize compute time

### 2. **Use Appropriately**
- Course-related work only
- Experimentation is encouraged

---

## Be a Good Neighbor

**DO:**
✅ Keep individual requests reasonable
✅ Use appropriate batch sizes
✅ Test with small examples first
✅ Be patient during peak hours
✅ Report issues constructively

**DON'T:**
❌ Run massive batch jobs during class time
❌ Leave long-running processes unattended
❌ Hog resources for hours

---

## Resource Management

### Respect Computing Limits

- **Token limits**: Keep prompts reasonable (< 4K tokens typical)
- **Concurrent requests**: Limit to 2-3 simultaneous calls
- **Long-running tasks**: Use off-peak times (evenings/weekends)
- **Model selection**: Use smaller models when appropriate

---

## Peak vs Off-Peak Hours

**Peak Hours** (High demand - be brief):
- During class sessions
- Assignment due dates
- Weekday afternoons (2-6pm)

**Off-Peak Hours** (Experiment freely):
- Early mornings (before 9am)
- Late evenings (after 9pm)
- Weekends

---

## Academic Integrity

### Use LLMs as Learning Tools

**Appropriate:**
- Understanding concepts
- Debugging your code
- Exploring ideas
- Learning prompt engineering
- Prototyping solutions

---

**Inappropriate:**
- Bypassing learning objectives
- Submitting AI work as entirely your own
- Violating assignment guidelines

---

## Citation & Transparency

When using LLM outputs in your work:

1. **Cite appropriately** per assignment guidelines
2. **Be transparent** about AI assistance
3. **Document your process** (prompts, iterations)
4. **Add your own analysis** and understanding

**Remember:** The goal is learning, not just completion.

---

## Prohibited Uses

**Absolutely NOT allowed:**

🚫 Generating harmful or offensive content
🚫 Attempting to bypass safety measures
🚫 Accessing others' prompts or data
🚫 Intentionally crashing the server
🚫 Sharing access outside the course
🚫 Commercial use of any kind

---

## Data Privacy & Security

### Protect Your Own Data

- **Don't submit** personal identifying information
- **Don't include** sensitive data in prompts
- **Assume** prompts may be logged
- **Remember** this is a shared resource

### Respect Others' Privacy

- Don't try to access others' work
- Don't share others' prompts without permission

---

## Quality Over Quantity

**Focus on thoughtful use:**

- **Iterate meaningfully** - don't just spam requests
- **Learn from outputs** - analyze what works
- **Refine your prompts** - quality over quantity
- **Document learnings** - build your skills

*One well-crafted prompt > 100 random attempts*

---

## Troubleshooting Etiquette

**If you encounter issues:**

1. **Check server status/connection** first
2. **Verify your code** - is it a client-side issue?
3. **Try a different model** if one is overloaded*
4. **Wait a few minutes** during peak times
5. **Report problems** to instructor
6. **Help others** if you've solved similar issues

---

## Communication Channels

**Report issues via:**
- Office hours
- Email instructor

**Include:**
- Time of issue
- Model used
- Error message (if any)
- What you were trying to do

---

## Collaboration Guidelines

**Encouraged:**
- Sharing prompt engineering techniques
- Discussing what works well
- Helping debug each other's code
- Sharing interesting findings

**Not Allowed:**
- Sharing solution code directly
- Copy-pasting others' work
- Coordinating to circumvent guidelines

---

## What If The Server Is Slow?

**During high load:**

- ⏰ Be patient - others are working too
- 🔄 Try again in 10-15 minutes
- 📉 Use a smaller/faster model
- 🕐 Consider working during off-peak hours
- 💡 Work on other tasks while waiting

**Remember:** We're all sharing this resource!

---

## When You're Done

**Clean up after yourself:**

- Close connections properly
- Cancel unnecessary running jobs
- Don't leave idle sessions open
- Log out of any interfaces

*Leave resources available for the next person*

---

## Emergency Protocols

**If you accidentally:**

- Started a resource-intensive job → Contact instructor immediately
- Caused an error → Don't retry repeatedly, report it
- Found a security issue → Report privately to instructor
- See suspicious activity → Alert instructor

---

## Red Flags to Avoid

**These indicate you're going off track:**

🚩 Running requests for hours uninterrupted
